# 노트북 우선 설정과 다중 head/seed 순차 실행

- 날짜: 2026-10-10 KST
- 상태: 구현됨, 제한된 테스트 및 임시 이미지/새 커널 실행 검증됨
- 배경: 사용자는 YAML보다 노트북 변수를 우선하고, 세 head 모두 생성하며, Windows에서 안전한 loader를 요구했다.
- 유지: add-adaface, MobileFaceNet 1024D, VGGFace2, 부모 ArcFace -> 새 세 head, 논문 조건과 구현 선택의 구분, 기존 완료 결과 불변.
- 변경: 00의 공통 설정을 JSON으로 저장하고 각 노트북 변수를 최우선 overlay한다. make_loaders는 크기/정규화/worker를 실제 dataset에 전달한다. 02/03/04는 seed/head 계획과 순차 실행을 공유한다. 노트북 worker는 0만 허용한다.
- 책임: modules/notebook_workflow.py는 설정/분할/계획/실행/재사용/summary를 담당한다. 기존 Trainer·CheckpointManager는 학습·저장·재개·export 검증을 유지한다. 노트북은 첫 설정 셀과 모듈 호출·결과 확인으로 구성한다.
- 데이터 흐름: 00 설정 -> 01 공통 목록 -> 02 seed별 부모 -> 03 seed별 세 head -> 04 export -> ronbun 별도 평가.
- 실행 보호: 01~04 기본 EXECUTE=False. 명시적으로 True를 선택해야 실행한다. smoke는 정식 가중치를 만들지 않는다. 완료 run은 지정 파일/설정/hash 검증 후 재사용하며 자동 최신 checkpoint 선택은 없다.
- 영향: 다섯 노트북, dataset.py, trainer.py의 실행 설정 기록, 새 notebook_workflow.py, common.yaml worker 기본, README와 테스트.
- 재실행 범위: kernel restart 후 00 설정 저장과 각 단계 계획 확인. 기존 결과 재학습은 필요하지 않으며 재사용 검증 불일치 시 새 출력 root를 선택한다.
- 검증 기준: 설정 우선순위, loader 실제 정규화, 0 worker, head×seed 수, 임시 이미지 학습/재사용/export, 실패 summary, 새 kernel 노트북 실행.
- 미실행: 전체 VGGFace2, 전체 데이터 무결성, UCFace 수치 재현, ronbun/Continuous FIQA.
