## 변경

- 다섯 노트북의 첫 코드 셀을 설정 진입점으로 통일. 00의 공유 JSON보다 현재 노트북의 변수 우선.
- dataset의 input_size/mean/std가 loader에 연결됨. 현재 MobileFaceNet의 112x112 밖 입력은 조용히 무시하지 않고 사전 차단.
- KEEP_RAW_RESULTS가 실제 Trainer와 checkpoint의 execution_settings에 연결됨. 완료 결과 재사용 시 당시 적용값과 현재 요청값을 구분.
- seed 목록과 세 head를 실제 순차 실행. 기본 계획은 부모 5개, 후속 모델 15개, export 15개. 실패하면 남은 작업까지 summary에 기록하고 중단.
- Windows/Jupyter 학습·검증 loader는 num_workers=0만 허용. formal training의 CUDA 필수 규칙 유지.
- 환경 출력은 파일 존재/크기·장치·branch·metadata count에 한정. 전체 archive/decode는 not_checked.
- 01~04 EXECUTE=False 기본값으로 실행 계획 확인 가능. 기존 완료 모델·기존 데이터 분할은 덮어쓰지 않음. 중단 checkpoint는 명시적으로 지정.
- 실행/해석 안내는 fine-tune/README.md. 기존 notebook 출력은 data/notebook_backups/에 로컬 보존 후 수정된 notebook 출력 제거.

## 독립 검증

1. 설정 우선순위, 전처리 수치/shape, worker 검증, 분할 불변, seed×head 순서, 실패 시 미실행 집계 검증.
2. 임시 이미지에서 CPU 제한 테스트: 2 seed 부모와 6 baseline을 1 epoch씩 학습, 완료 파일 재사용 및 6 export 검증. 이 CPU 경로는 테스트에서만 device 함수를 치환하며 정식 경로는 CUDA 필수.
3. 각각 새 Python 3.11 Jupyter kernel로 00~04 전체 실행: 임시 이미지, 1 seed, 8D 모델, batch 2, 1 epoch. 실제 CUDA 학습과 세 head export 파일 3개 확인. worker=0 확인. 원본 notebook 설정은 해당 임시 검증값으로 저장하지 않음.
4. 중단 후 일부 seed만 선택한 재개와 보존 설정 변경: 기존 설정 사본을 보존하고 새 재개 설정 사본을 기록하는 테스트 통과.
5. 노트북 nbformat 검증·Python 구문 검사·git diff --check 통과.

검증 도중 Jupyter 테스트 실행기의 Windows Proactor/zmq 경고가 있었으나 selector thread fallback으로 다섯 kernel 실행 모두 성공했다. 이는 DataLoader worker 오류가 아니다.

전체 VGGFace2 학습, 전체 데이터 무결성, UCFace 수치 재현, ronbun/Continuous FIQA 실험은 미실행이다. 현재 변경은 노트북 제어와 캠페인 실행의 수정이며 미공개 논문 recipe를 새로 확정하지 않는다.
