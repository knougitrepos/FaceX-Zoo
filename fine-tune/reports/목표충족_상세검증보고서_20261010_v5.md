## 2. 결함 심층 분석 및 2차 보완 내역 (Audit Findings & Root Cause Fixes)

### 📌 결함 1: 설정 hash에 학습 조건과 데이터 목록의 실제 내용 미포함 ([P2])

#### 1. 문제 원인 분석
- `fine-tune/modules/checkpoint_manager.py`의 `extract_model_and_train_config()`는 데이터셋의 단순 경로 문자열(`train_list`, `val_list`)만 저장하고 인덱스 파일 본문의 암호학적 해시를 저장하지 않았습니다.
- 또한 `training` 설정 추출부에서 `batch_size`, 학습률 감쇄 마일스톤(`milestones`), 감쇄율(`lr_decay_ratio`)이 누락되어 있었습니다.
- 1차 시도에서 추가 보완되었으나, 독립 검증 과정에서 다음 4가지 잠재적 취약점이 추가로 발견되었습니다:
  1. `config` 딕셔너리에 `training` 키가 없으면 `train_loader`, `scheduler`, `optimizer`를 직접 넘겨도 추출 결과가 `{}`로 반환되는 결함.
  2. 상대 경로로 지정된 `train_list`의 경우 `os.path.isfile()` 실패로 `train_list_hash`가 `None`으로 산출되는 문제.
  3. `PyTorch Subset` 등 래퍼 데이터셋 사용 시 원본 `FaceImageDataset` 속성에 접근하지 못하는 문제.
  4. 빈 설정 딕셔너리(`expected_config={}`) 전달 시 교집합 비교 방식으로 인해 모든 검증이 우회되는 결함.

#### 2. 코드 레벨 완전 해결 조치
- **`extract_train_config` / `extract_model_and_train_config`**:
  - `train_loader.dataset`이 `Subset`, `ConcatDataset` 등으로 래핑되어 있어도 원본 데이터셋까지 재귀적으로 언래핑하여 `data_root`, `index_file`, `target_size`, `pixel_mean`, `pixel_std`를 직접 추출.
  - 상대 경로 인덱스 파일(`train_rel.txt`)을 `data_root`와 결합하여 디스크 상의 실제 파일을 찾아 SHA-256 해시를 산출.
  - `FaceImageDataset`에 `pixel_mean=127.5`, `pixel_std=128.0`을 명시적으로 노출하여 전처리 파라미터가 라이브 로더로부터 직결 추출되도록 개선.
  - `config` 인자가 `None`이어도 전달된 라이브 `scheduler`(`milestones`, `gamma`), `optimizer`(클래스명, `lr`, `weight_decay`), `train_loader`(`batch_size`)로부터 완전한 `training` 섹션을 자동 구축.
- **`compare_configs`**:
  - `full_strict: bool = False` 모드 도입: 정식 `expected_config`가 주어진 경우, 체크포인트에 존재하는 항목이 현재 설정에서 누락되었거나 변경된 경우 모두 mismatch로 감지.
  - `Training` 섹션(`batch_size`, `milestones`, `lr_decay_ratio`, `total_epochs`)과 `Dataset` 섹션(`data_root`, `raw_root`, `train_list_hash`, `val_list_hash`) 완벽 비교.
- **`compute_config_hash`**:
  - `numpy` 및 `torch` 텐서 스칼라/배열 직렬화 예외를 방지하기 위해 `default=_json_default` 핸들러 추가.

### 📌 결함 2: 설정 메타데이터가 없는 체크포인트의 무검증 재개 허용 ([P2])

#### 1. 문제 원인 분석
- 체크포인트 파일에 `config` 또는 `config_hash`가 누락된 경우 검증을 건너뛰고 조용히 에포크 복원 및 재개를 허용하던 결함.
- 독립 검증 과정에서 추가로 발견된 취약점:
  1. 빈 딕셔너리(`config: {}`)와 더미 해시를 가진 체크포인트가 `isinstance(dict)` 조건을 통과하여 무검증 재개되는 문제.
  2. 체크포인트 내부의 `config` 내용을 임의로 변조했을 때 체크포인트 자체의 `config_hash`와의 불일치를 검증하지 않던 무결성 검증 부재.
  3. `resume_checkpoint` 호출 시 `expected_config`가 `None`인 경우 전달된 `scheduler` 및 `optimizer` 파라미터 불일치를 검사하지 않던 결함.

#### 2. 코드 레벨 완전 해결 조치
- **`CheckpointManager.resume_checkpoint()`**:
  - `strict_config: bool = True` (기본값) 및 `allow_unverified_resume: bool = False` (기본값) 적용.
  - `config`가 `None`이거나 딕셔너리가 아니거나 빈 딕셔너리(`not ckpt_cfg`)이거나 필수 백본/헤드 메타데이터가 누락된 경우 즉시 `ValueError` 발생 차단 (**Fail-Closed**).
  - 체크포인트 자체의 내부 무결성 검증 추가: `ckpt_hash != compute_config_hash(ckpt_cfg)` 감지 시 내부 변조로 즉각 `ValueError` 차단.
  - `expected_config`가 `None`인 저수준 직접 호출 환경에서도 전달된 `optimizer` 및 `scheduler`로부터 현재 실행 설정을 추출하여 체크포인트의 `training` 조건과 대조 검증.
  - 임의의 우회 게이트(`if "training" in ckpt_cfg and "training" in effective_curr_cfg:`)를 제거하고, `expected_config`가 주어지면 해시 일치성을 무조건 엄격 검증.
  - 검증되지 않은 구버전 체크포인트를 불가피하게 불러와야 하는 경우 `allow_unverified_resume=True` 또는 `strict_config=False`가 명시될 때만 경고 로그(`logger.warning`)와 함께 허용.
