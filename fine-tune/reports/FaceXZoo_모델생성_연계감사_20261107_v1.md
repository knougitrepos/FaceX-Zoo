## 1. 실제 생성 계획

현재 저장 설정과 노트북이 구성하는 계획은 다음과 같다.

- Parent: VGGFace2로 학습하는 **MobileFaceNet backbone + ArcFace head 1개**.
- 후속 학습: SurvFace·TinyFace·SCFace 각각 ArcFace·AdaFace·MagFace·CosFace 1개씩, seed 8972. **3개 데이터셋 × 4개 loss × 1개 seed = 12개 모델**.
- Export: 위 후속 모델의 backbone 12개. Parent는 이 12개와 별도다.
- 모든 후속 모델은 동일한 완료 parent backbone에서 독립적으로 시작한다. TinyFace → SCFace → SurvFace 순차 학습 구성이 아니다.

현재의 “loss당 1개”는 **각 데이터셋 안에서 loss당 1개**라는 뜻이다. 전체 데이터셋을 합쳐 4개만 만드는 설정은 아니다. [fine-tune README](F:/FaceX-Zoo/fine-tune/README.md:87)의 60개 설명은 5 seed 기본 예시이며 현재 저장된 1 seed 설정과 구분해야 한다.

설정 근거는 [notebook_settings_mobilefacenet.json](F:/face_datasets/.state/facex/shared_v1_boundary/notebook_settings_mobilefacenet.json)과 각 노트북 첫 설정 셀이다. 저장 설정 SHA-256은 96106a2078ea4f5d5efb2dce5e0b714a2a2dabdb642bc56286e8e3b6493dda60이다.

주요 학습 조건은 1024D, MobileFaceNet, Adam, 40 epochs, batch 64, dropout 0.6, learning rate 0.001, 10·20·30 epoch에서 0.1배 감쇠, drop_last=False다. Downstream margin은 ArcFace m=0.6/s=64, CosFace m=0.3/s=64, AdaFace m=0.4/h=0.333/s=64, MagFace (10,110,0.45,0.8,20)/s=64다.

논문 범위 표기는 기존 연구 결정대로 유지한다. Downstream 기준 설정을 따르는 구성과 FaceX-Zoo·로컬 구현 선택을 구분하며, parent ArcFace m=0.35/s=32와 연구자가 고정한 분할까지 “UCFace 완전 재현”이라고 부르지 않는다. 이번 감사에서는 논문을 새로 대조하지 않았으며 현재 코드·설정의 실행 준비를 검사했다.

예상 최종 parent 파일 F:/models/facex/checkpoints/shared_v1_boundary_mobilefacenet/pretrain_arcface_seed8972/pretrain_mobilefacenet_1024d.pt는 감사 시점에 없다. Parent가 40 epochs를 완료하고 최종 체크포인트·완료 메타데이터·hash를 생성해야 03의 선행조건을 충족한다. 현재 복구 파일을 폐기하거나 처음부터 다시 학습해야 할 근거는 발견하지 않았다.

아직 실제 export가 없으므로 **향후 생성될 최종 가중치를 ronbun에서 읽고 같은 입력에 대해 추론하는 검사**는 남아 있다. 인계 완료 조건은 다음과 같다.

1. Parent 1개와 downstream 12개가 각각 정식 완료되고, 중단·smoke 결과가 섞이지 않는다.
2. Export 12개와 sidecar의 파일 hash·차원·전처리·학습 identity 출처가 일치한다.
3. ronbun의 등록 함수가 실제 export를 strict load해 checkpoint별 ModelSpec을 만든다.
4. ronbun YAML에 정확한 ModelSpec 경로와 training_dataset을 명시한다.
5. 첫 실제 1024D 추론과 CR-FIQA 입력 생성에서 CUDA·값의 유한성·cache 계약을 확인한다.

FaceX-Zoo의 생성 완료는 모델 인계를 위한 조건이다. ronbun의 보정 학습·평가 완료는 소비 측에서 별도로 확인한다.

## 4. 남은 코드 위험 FZ-1 — 공용 잠금의 최초 쓰기 실패

중요도 **P2**, 상태 **재현됨·미수정**. 위치: [shared_storage.py](F:/FaceX-Zoo/fine-tune/modules/shared_storage.py:87).

독점 lock 파일을 만든 후 PID·host·token을 JSON으로 기록하는 동작이 try/finally 밖에 있다. 이 최초 기록에 합성 OSError를 발생시키자 빈 lock이 남았으며, 다음 정상 시도가 FileExistsError로 막혔다.

이 함수는 전처리, 검증 표식, 입력 cache, export의 공용 저장 경로에서 쓰인다. 쓰기 오류가 생긴 경우 재시작이 막힐 수 있다. 현재 실제 데이터나 체크포인트가 손상됐다는 증거는 아니며, 정상 경로 테스트 통과와도 양립한다.

향후 수정은 소유권을 얻은 lock의 최초 기록부터 예외 정리 범위에 포함해야 한다. 다른 프로세스의 lock은 유지해야 하므로 일괄 삭제로 해결하면 안 된다. 이번 요청은 감사보고서 작성이므로 코드와 실제 lock을 변경하지 않았다.

## 5. 검증 범위와 운영상 한계

이번 감사에서 FaceX-Zoo 관련 **114개 pytest 검사 통과**, 실패·skip 0개다. Resume 필수 상태, immutable 검증 표식, 입력 무결성, 공유 연구 분할, export 복구, backbone recipe, 전처리 정책을 포함한다. SimilarityTransform.estimate 관련 FutureWarning 12건은 테스트 실패가 아니다.

명령은 저장소 루트 기준 다음과 같다.

~~~powershell
py -3.11 -B -m pytest fine-tune/tests/test_resume_state_contract.py fine-tune/tests/test_immutable_verification.py fine-tune/tests/test_input_integrity_regressions.py fine-tune/tests/test_research_handoff.py fine-tune/tests/test_export_recovery.py fine-tune/tests/test_backbone_recipe.py fine-tune/tests/test_preprocessing_v2.py -q
~~~

이번 실제 환경은 Python 3.11.9, PyTorch 2.7.1+cu118, CUDA runtime 11.8, GTX 1080 Ti이며 CUDA 사용 가능 상태였다. 전체 40-epoch 학습, downstream 이미지 전체 decode, 실제 export 12개, ronbun 실제 추론·평가를 이번 감사에서 실행하지 않았다. 테스트 성공을 실제 인식 성능이나 모든 학습 실행의 성공으로 확대하지 않는다.

현재 KEEP_RAW_RESULTS=True다. 입력 원본과 사전학습 checkpoint는 결과 정리 옵션의 삭제 대상이 아니다. 완료 결과를 덮어쓰지 않고 현재 namespace와 명시적 run을 재사용해야 한다.

이번 범위의 판단은 **02 재개 근거 확보 → parent 완료 확인 → 03 최초 downstream 준비 및 12개 독립 학습 → 04 export 검사 → ronbun 등록** 순서다. Parent 미완료, downstream 전처리 미완료, export 부재는 남은 작업이며, FZ-1은 별도로 개선할 코드 결함이다.
